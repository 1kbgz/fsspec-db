Paths and metadata¶

fsspec-db paths are absolute, protocol-free paths once a filesystem is constructed.

import fsspec

fs = fsspec.filesystem("db+sqlite", database="app.db")
fs.ls("/main")

Grammar¶

Path

Meaning

/

Root, listing schemas/catalogs.

/{schema}

Schema directory, listing tables and views.

/{schema}/{relation}

Relation directory, listing metadata facets.

/{schema}/{relation}/columns

Column facet directory.

/{schema}/{relation}/columns/{column}

Column metadata item.

/{schema}/{relation}/indexes

Index facet directory.

/{schema}/{relation}/indexes/{index}

Index metadata item.

/{schema}/{relation}/constraints

Constraint facet directory.

/{schema}/{relation}/constraints/{constraint}

Constraint metadata item.

/{schema}/{view}/depends_on

View dependency facet directory.

/{schema}/{view}/depends_on/{relation}

A relation the view reads, with target.

/{schema}/{view}/definition.sql

View definition SQL.

/{schema}/{relation}.arrow

Materialized relation as Arrow IPC stream.

/{schema}/{relation}.parquet

Materialized relation as Parquet.

/{schema}/{relation}.csv

Materialized relation as CSV.

/{schema}/{relation}.jsonl

Materialized relation as line-delimited JSON.

/{schema}/{relation}.sql

Relation DDL text.

SQLite normally exposes the default database as /main. Native backends render relation .sql data paths. The direct PyDatabaseFileSystem adapter raises NotImplementedError for relation DDL rendering; view definition.sql remains available when its backend implements view_definition.

Listing¶

fs.ls("/", detail=False)
# ["/main"]

fs.ls("/main", detail=False)
# ["/main/users", "/main/active_users"]

fs.ls("/main/users", detail=False)
# ["/main/users/columns", "/main/users/indexes", "/main/users/constraints"]

detail=True returns fsspec info dictionaries:

fs.ls("/main/users/columns", detail=True)

Metadata¶

fs.info("/main/users")
fs.info("/main/users/columns/id")
fs.info("/main/users/indexes/idx_users_name")

Relation info includes kind and may include row_count. Column info includes database type, nullability, ordinal position, and primary-key status.

Read Shaping¶

Four query parameters are available on materialized relation paths:

Parameter

Example

Status

columns

/main/users.arrow?columns=id,name

Selects a column list.

limit

/main/users.parquet?limit=100

Adds LIMIT.

offset

/main/users.arrow?limit=20&offset=20

Skips rows before applying the limit.

where

/main/users.arrow?where=score > 10

Adds a WHERE predicate (see below).

Query values are URL-decoded, so percent-encoded predicates such as ?where=score%20%3E%2010 are equivalent to the unencoded form.

data = fs.cat_file("/main/users.arrow?columns=id,name&limit=10&where=id > 0")

where predicate pushdown¶

The where value is parsed as a single boolean SQL expression with a dialect-aware parser, re-serialized from its AST, and appended as a WHERE clause. Because only a parsed expression is ever emitted, multi-statement or non-expression payloads are rejected with a ValueError rather than interpolated:

fs.cat_file("/main/users.arrow?where=score > 10")          # ok
fs.cat_file("/main/users.arrow?where=1); DROP TABLE x;--")  # rejected

fs.query() accepts arbitrary SQL beyond a single predicate.

Write Paths¶

Data writes use the same materialized relation paths as reads:

with fs.open("/main/users.arrow", "ab") as f:
    f.write(arrow_ipc_bytes)

The incoming file extension controls decoding. .arrow and .parquet carry their own schema. .csv and .jsonl are decoded using the database table schema.

Metadata dictionaries¶

info() and ls(detail=True) return ordinary fsspec dictionaries with these common keys:

Key

Meaning

name

Absolute fsspec-db path, without protocol.

type

"directory" for schemas, relations, and facets; "file" for metadata items and materialized data.

size

Byte size when known. Materialized table reads usually learn size only after encoding.

kind

fsspec-db object kind, such as schema, table, view, column, index, or constraint.

Extra metadata is stored directly in the same dictionary:

Path

Extra fields

Relation directory

kind, optional row_count, optional size_bytes.

Column item

data_type, nullable, ordinal, primary_key, optional default.

Index item

columns, unique, optional method.

Constraint item

kind, columns, optional references, optional expr.

Data file

format, dialect, size_known.

Column values¶

/{schema}/{relation}/columns/{column} is both a metadata item for info() and a JSON array of distinct, sorted values for reads. limit and offset bound column-value reads; the default limit is 100.

Write modes¶

Operation

Behavior

open(path, "wb")

Replaces relation rows when the write commits.

open(path, "ab")

Appends rows when the write commits.

pipe_file(path, bytes) / put_file(local, path)

Overwrites by default.

pipe_file(..., mode="append") / put_file(..., mode="append")

Appends.

pipe_file(..., mode="create") / put_file(..., mode="create")

Raises FileExistsError for an existing target; does not create a table.

Supported open modes are r, rb, w, wb, a, and ab. Exclusive-create and update modes raise NotImplementedError. Writes decode the completed encoded stream at commit time. Unclosed native write handles are discarded.

DDL and cache controls¶

allow_ddl=False is the default. Guarded mkdir, rm_file, and mv raise PermissionError unless enabled. Raw query() is not restricted by that flag.

With DDL enabled, mkdir("/schema/relation", schema=arrow_schema) creates a table; sql= accepts explicit creation SQL. rm_file("/schema/relation") drops the relation, while a relation path with an extension deletes its rows. mv renames relations within one schema; cross-schema moves raise NotImplementedError.

ls(..., refresh=True) and info(..., refresh=True) bypass cached introspection. invalidate_cache(path=None) clears all Python and available Rust introspection cache entries, even when a path is supplied. Listing cache options include use_listings_cache, listings_expiry_time, and max_paths.
